GovCare EHR — Reusable Clinical PDF Import and Review (V57)
Delivered: 21 October 2026

AUTOMATIC READING FOLLOW-UP
Newly selected or dropped local PDFs now start extraction immediately. Selecting an authorized EHR report also starts a read. The queue uses current state when asynchronous results arrive, so new files and earlier previews are retained. Reading progress is visible and an immediate busy guard prevents duplicate starts. Only newly added sources are read; explicit re-read remains available. Applying values and saving clinical reports still require confirmation.
Actual browser verification covered file selection, appending files, drag/drop, saved EHR selection, re-reading and all ten generated PDFs without a Read-button click. Clinical counts and existing manual form values remained unchanged. The targeted Node suite passed 34 tests. Evidence: verification/pdf-auto-read/browser.json, node-tests.log, vite-build.log, desktop.png and mobile.png.

RESULT
Reading a report is repeatable and independent of saving source documents or running an assessment. Existing reports are reused by hospital + patient + SHA-256. Reading, re-reading, clearing a selection, or comparing sources does not insert clinical observations, FHIR Observations, or predictions.

ROOT CAUSES
1. The old checksum check returned a blocking conflict before extraction; one duplicate aborted a multi-file request.
2. The extraction endpoint saved the attachment, report, clinical observations and final FHIR Observations during a read operation.
3. The form selected a dated/latest/last candidate automatically, hiding competing results and overwriting values without field approval.
4. Repeated manual edits could lose MANUAL_OVERRIDE provenance. Missing inputs and unreported history needed clearer completion guidance.
5. Label/unit handling missed spaced eGFR units, “Estimated GFR”, abbreviated hemoglobin and conversions. A filename was not a reliable description of its actual contents.
6. Installed Chrome returned failed or empty binary PDF fetches; clean Chromium and requests carrying an Origin header succeeded. The bounded, authenticated JSON preview avoids that failing browser path. Browser configuration and CORS permissions were not relaxed.
7. Draft summaries did not include form data, but the page never fetched draft details for restoration. Initial autosave also risked replacing a saved draft with the calculated age alone.

IMPLEMENTATION
Backend:
- ClinicalPdfImportService separates preview, saved-source extraction, protected file preview and explicit source saving.
- ClinicalPdfExtractionController keeps the existing extract routes and adds authorized saved-source listing, explicit save and protected preview routes.
- ClinicalPdfExtractionService normalizes supported units, preserves original text/value/unit, recognizes the supplied labels, rejects qualified numbers as exact measurements, and reports unsupported measurements and OCR requirements.
- Patient identity is compared with stored patient number, NIC and/or name where printed. A mismatch suppresses candidates and blocks source save, even if the confirmation checkbox is selected. An image-only or unidentified PDF remains unverified and requires explicit identity confirmation before saving its source.
- Save uses a transaction, a PostgreSQL advisory lock scoped to hospital/patient/hash, and the existing unique checksum index. Concurrent identical saves return the same stored identifiers.
- ClinicalPersistenceService stores source metadata without generating laboratory observations.
- V49__clinical_pdf_reviewed_sources.sql adds extraction metadata, replaces_report_id and revision_reason. The existing version field records reviewed corrections. A new correction requires a reason and retains the original source and values.
- CkdPredictionService requires approval metadata for imported inputs, validates referenced reports against the selected patient/tenant, and rejects invalid input ranges. Model coefficients, artifacts and the 17-feature model contract remain unchanged.
- Saved PDF preview uses a 15 MB bounded authenticated JSON response with no-store headers. The frontend verifies the association and PDF signature and opens a local Blob URL; bearer tokens never appear in viewer URLs. Existing download routes remain available.
- General saved PDF responses carry no-store semantics. Configured CORS, document permissions and patient authorization remain enforced.

Frontend:
- ClinicalPdfImportWorkspace provides drag/drop, browsing, a removable queue, searchable saved-report checkboxes, per-file status, duplicate reuse, re-read, preview, open and explicit save/revision actions.
- Up to ten reports are queued, with a 15 MB per-file limit. Local PDFs are read independently with at most three requests in flight, avoiding the server's aggregate multipart limit. One failed file leaves the other results available.
- The comparison view displays current, original and normalized values, source files, report dates and verification status. Competing values need explicit source selection and field approval. The bulk approval action only selects unambiguous empty fields.
- Applying values requires identity confirmation. Reading alone never changes the form. Clearing a selection preserves saved records and form values.
- Manual overrides retain their original source, value, unit, text and references across further edits and re-reading. Unknown history stays missing; it is not converted to No.
- All missing required model inputs are listed with focus actions. Incomplete or invalid data cannot call the assessment endpoint.
- Partial drafts retain values, provenance and the optional manually entered measurement time. Draft details are loaded for restoration. Autosave starts after an edit rather than overwriting an existing draft on initial load.
- Desktop uses a comparison table; mobile uses readable cards. Styling uses existing GovCare theme tokens.

PROVENANCE AND FHIR
- Saving source evidence creates a preliminary DocumentReference and linked Provenance, with a replacement relationship for reviewed corrections. It does not create laboratory Observations or a RiskAssessment.
- Explicit approved assessment execution retains the existing assessment/RiskAssessment workflow. It stores reviewed input snapshots and original-value metadata. Explicit manual/calculated entries follow existing observation persistence rules.
- A report date is distinct from a specimen collection time. The supplied 28/09/2026 dates are preserved as report dates. No upload time or fabricated midnight is used as a clinical observation time.
- Imported values remain unverified. No clinical verification is inferred from successful parsing, duplicate detection, identity confirmation or model execution. Existing historical records are retained.

QA ISOLATION AND REPRODUCTION
All writes used a new, clearly labelled SYNTHETIC SOFTWARE QA facility with dedicated synthetic patients and test accounts. No existing account password or role was changed and no existing clinical records were edited or deleted. The provided PDFs identify TEST-PAT-001 / TEST PATIENT and must not be associated with an unrelated real patient.
The local QA credential/session file is outside the project under the user's .codex/tmp directory and is excluded from delivery. A fresh QA run can set GOVCARE_PDF_QA_SESSION to a new path outside the project, then run scripts/pdf-reuse-qa-db.mjs --provision, the live verifier, browser verifier and revision verifier. The initial-save verifier expects a fresh QA facility. Browser verification requires Playwright and a compatible installed browser or its headless shell. Existing V44+ verification evidence and the V56 delivery are retained.

KNOWN LIMITATIONS
- No OCR engine is configured. Image-only PDFs need OCR or manual entry; they never produce fabricated measurements.
- Extraction uses supported label/unit patterns rather than general medical document understanding. Unsupported or ambiguous results require review. The legacy parser confidence score is heuristic, not calibrated clinical certainty.
- Protected preview uses base64 JSON and therefore has encoding overhead; it is capped at 15 MB.
- Historical extracted records are preserved rather than retroactively reclassified or deleted.
- Existing clinical verification, model eligibility and clinician review remain separate from extraction approval.
