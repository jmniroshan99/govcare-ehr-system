# Staff Management Test Checklist

## Access control

- [ ] Super Admin can open `/admin/staff`.
- [ ] Hospital Admin can open `/admin/staff`.
- [ ] Doctor, Nurse, Records Officer, Laboratory, Pharmacy and Radiology roles receive HTTP 403 for `/api/admin/staff`.
- [ ] Unauthorized roles do not see the Staff Management sidebar item.

## Hospital scope

- [ ] Super Admin can list and create staff for any hospital.
- [ ] Hospital Admin sees only their hospital.
- [ ] Hospital Admin cannot submit another `hospitalId`.
- [ ] A department from another hospital is rejected with HTTP 400.
- [ ] Hospital transfer is rejected for Hospital Admin and allowed for Super Admin.

## Account creation

- [ ] Employee number is generated by Spring Boot/PostgreSQL.
- [ ] Duplicate email returns HTTP 409.
- [ ] Password is stored only as a BCrypt hash.
- [ ] Role permissions come from `role_permissions`.
- [ ] Hospital Admin cannot assign Hospital Admin or Super Admin.
- [ ] The temporary password is returned only in the create response.

## Role behavior

- [ ] Records Officer is redirected to `/patients/register`.
- [ ] Laboratory Technician is redirected to `/laboratory`.
- [ ] Doctor is redirected to `/doctor`.
- [ ] Pharmacist is redirected to `/pharmacy`.
- [ ] Hospital Admin is redirected to `/admin/staff`.

## Account lifecycle

- [ ] Deactivated staff cannot log in.
- [ ] An admin cannot deactivate their own account.
- [ ] Role changes take effect on the next API request.
- [ ] Password reset sets `must_change_password=true`.
- [ ] Staff are forced to change a temporary password before accessing modules.
- [ ] Password change clears `must_change_password`.

## Audit

- [ ] Staff creation is logged.
- [ ] Staff update is logged.
- [ ] Role and department changes are logged.
- [ ] Activation/deactivation is logged.
- [ ] Password reset is logged.
- [ ] Hospital transfer is logged.
