GovCare EHR - Clinical PDF testing workflow V59
Delivery date: 2026-10-21

IMPLEMENTED BEHAVIOR
The existing React/Spring/PostgreSQL/FHIR application now provides actual PDF
upload -> extraction -> explicit review -> verified patient observations ->
CKD readiness, with no model or authentication replacement.

Use the existing three-step CKD workspace:
1. Select an authorized synthetic testing patient and add one or more PDFs.
   Actual valid content is stored immediately, including scans, undated reports,
   incomplete panels and reports without recognizable measurements.
2. Review each uploaded source. Correct values and units; select results;
   supply actual collection dates. Missing parameters can be transcribed from
   the source. Enter a review note and explicitly confirm patient association.
   Choose Confirm & Save Verified Observations to persist reviewed results.
3. Confirmed supported measurements populate the assessment. Complete the
   remaining required inputs. The server validates readiness before Run.

ROOT CAUSES AND REPAIR
- The earlier workflow conflated patient identity/extraction completeness with
  permission to associate a test document. Mismatched printed identities cleared
  all measurements even for synthetic demonstrations. A stored synthetic-patient
  policy now permits reviewed test association without changing strict matching
  for other patients.
- Previous preview/autofill only changed the assessment draft; it did not create
  a linked, dated, verified clinical observation. The new verification service
  invokes existing verified-measurement persistence and explicitly links the
  result to the source document and FHIR DocumentReference.
- Filename and client MIME were insufficient upload checks. Actual PDF signature,
  PDFBox parsing, encryption/resource limits and active-content checks now decide
  PDF acceptance; generic MIME and unusual filenames are supported.
- Extraction covered mostly CKD numeric inputs, leaving CBC and other chemistry
  unsupported. Explicit analyte mappings and typed unit conversions now recognize
  the requested CBC/renal/electrolyte inputs without reinterpreting generic glucose
  as fasting, blood urea as BUN, or serum albumin as urine ACR.
- Clinical ingest previously could duplicate an attachment uploaded through the
  general patient-document screen. Scoped checksum lookup now reuses it.
- Readiness could rely on a browser review flag. New uploaded sources require
  matching confirmed database evidence; setting sourceVerified in a request does
  not make an unconfirmed PDF observation ready.

TEST-PATIENT IDENTITY POLICY
Eligibility is determined on the server from BOTH stored patient risk flags:
  SYNTHETIC_RESEARCH_DEMONSTRATION
  NOT_A_REAL_PATIENT
The patient must still pass ClinicalPatientAccess and hospital authorization.
Names containing TEST, URLs, filenames and client-supplied booleans do not enable
this exception. Existing research demonstration records use these flags. Do not
mark a real person synthetic to bypass identity matching.

Eligible documents and verified observations are marked TEST_DOCUMENT. Printed
identifiers remain unverified source information; they are not copied into the
selected patient's demographics. Missing/mismatched identity needs explicit
review. Other patients retain strict mismatch blocking. A test-classified source
cannot be reused as real-patient clinical evidence if its designation changes.

DATABASE / FHIR
Flyway V50__clinical_pdf_upload_and_verification.sql adds document classification,
workflow states, observation source metadata and append-only review records.
It was applied successfully to the local PostgreSQL database.

Workflow states: UPLOADED, PENDING_EXTRACTION, EXTRACTION_COMPLETED,
PARTIAL_EXTRACTION, MANUAL_REVIEW_REQUIRED, CLINICAL_DATA_VERIFIED,
EXTRACTION_FAILED. Upload and extraction remain distinct response fields.
Extraction completeness does not imply that all model inputs exist.

Observations retain patient/hospital/report/document association, original
extraction, original units, normalized values, reviewed values/units, actual
collection time, review note and classification. Conflicting corrections to the
same report/analyte/time supersede earlier observations and mark corresponding
FHIR resources entered-in-error. Original records are retained.

Source documents use FHIR R4 DocumentReference and Provenance. Confirmed
measurements use existing FHIR Observation persistence with final status,
patient reference, collection time, valueQuantity, derivedFrom document linkage
and TEST_DOCUMENT classification tags. Clinician review and audit entries remain.
No assay-specific LOINC codes are invented.

NORMALIZATION / MAPPING
Supported additions include PCV, RBC, WBC, platelets, blood urea, sodium, calcium,
serum albumin, generic glucose and pre/post-HD urea alongside existing CKD inputs.
Examples: creatinine umol/L /88.4 -> mg/dL; Hb g/L /10 -> g/dL;
ACR mg/mmol *8.84 -> mg/g; albumin g/dL *10 -> g/L;
urea mg/dL /6.006 -> mmol/L; PCV L/L *100 -> %;
WBC/platelets cells/uL /1000 -> 10^9/L; calcium mg/dL *.2495 -> mmol/L.
Unknown/ambiguous units do not become verified values. Unsupported lines remain
available in extraction source details. Historical/competing results require review.

Reference checks (authoritative conversion tables / analyte definition):
https://backend.mayocliniclabs.com/order-tests/si-unit-conversion.html
https://www.niddk.nih.gov/health-information/professionals/clinical-tools-patient-management/kidney-disease/identify-manage-patients/evaluate-ckd/assess-urine-albumin
Clinical parameter mappings are explicit engineering rules; local clinical
governance review remains necessary before production adoption.

LIMITATIONS / CONFIGURATION
- OCR is optional and disabled locally. Set GOVCARE_PDF_OCR_ENABLED=true and
  GOVCARE_PDF_OCR_EXECUTABLE to an installed local Tesseract binary, plus language
  data. Scans return OCR_REQUIRED when unavailable; no successful extraction is
  claimed. Low-confidence results require source review. An installed OCR engine
  was not exercised in the live local run; fallback and parser behavior were tested.
- Automatic recognition uses explicit text patterns. Complex tables, uncommon
  layouts and ambiguous dates may need manual review; no universal parser is claimed.
- Upload is synchronous and bounded (clinical importer: 15 MB, 200 PDF pages;
  OCR: at most ten pages, per-page timeout and total processing deadline).
- Active PDF content is rejected; this is structural validation, not a replacement
  for an institution's malware scanner. No external OCR service receives documents.
- Existing clinical monitoring may preserve newer undated or conflicting historical
  sources for review rather than overwrite them with an uploaded older measurement.
  PDF upload does not override chronology, chronicity or model eligibility rules.
- Research scores retain the existing validation/calibration limitations. No model
  probabilities, history flags, measurement dates or missing values are fabricated.
- The design-tool sign-in service was unavailable; the review interface uses the
  current GovCare component library, layout and theme tokens.
