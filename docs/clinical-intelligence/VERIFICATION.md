Reproduce from the repository root on this Windows environment:

```powershell
mvn.cmd -B test -f spring-api/pom.xml -Dgovcare.clinical.rules.qa.output=../verification/clinical-intelligence-v2
.venv-cdss312/Scripts/python.exe ML_Server/manage.py test renal_service --noinput
.venv-cdss312/Scripts/python.exe -m unittest discover -s ml-training/tests -p test_cdss_enhancement.py
npm.cmd run build
.venv-cdss312/Scripts/python.exe ml-training/benchmark_cdss.py --output ml-training/runs/<new-run-name>
```

Use a new benchmark output directory to preserve prior artifacts. Browser verification requires the existing frontend on `127.0.0.1:5300`, Playwright and Chrome; set `GOVCARE_PLAYWRIGHT_MODULE` and `GOVCARE_CHROMIUM_EXECUTABLE` to installed locations before running `node scripts/verify-clinical-intelligence-browser.mjs`. It creates/removes only its own temporary HTML harness and uses an isolated headless browser context.

The native verifier reads local connection settings privately, creates a randomly named synthetic database, runs its own child services, and terminates only those services. It retains the synthetic database for inspection. Run with `python scripts/verify-clinical-intelligence-stack.py` using the system Python with psycopg/requests. Never publish local environment files or temporary service tokens.

The 12ui design workflow was attempted with the retained existing style/layout. Its remote authentication service was unreachable; no generated design was substituted. The implementation preserves GovCare styles and underwent local rendered review. Poppler is unavailable on this machine; the existing Java PDFBox renderer provided visual QA instead.

The active local stack is reloaded after compilation; [runtime evidence](../../verification/clinical-intelligence-v2/runtime.json) records health/version checks without credentials. Reload applies the additive V48 migration; legacy session metadata stays empty and therefore unverified.
