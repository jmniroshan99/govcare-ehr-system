# Shared GovCare theme and component system

## Visual reference and coverage

The supplied Predictive Clinical Intelligence screenshot defines the shared visual language: clean mint surfaces in light mode, the existing dark green identity in dark mode, rounded cards, compact icon tiles, readable teal headings and generous separation between tasks. All role dashboards use the common page hierarchy while retaining their role-specific definitions and backend aggregation.

The theme is loaded once by `src/index.css`. Shared components propagate it to registration, consultations, nursing, admissions, wards/beds, pharmacy, laboratory, radiology, patient/guardian workflows and administrative screens. Existing `page-hero` sections inherit the new system; 25 additional legacy page headers were explicitly marked for it. The coverage document audits all 60 page source files, including aliases and compatibility pages. It is a source audit, not a live visual certification.

## Dark and light behavior

The preserved dark palette uses background `#061F1B`, surface `#0D2924`, primary `#00C9A7` and light text. The light palette uses background `#F4FAF8`, white surfaces, primary `#008F78` and text `#12312D`. Colors belong in `colors.ts`; components use semantic variables or mapped Tailwind utilities.

Principal variables are `--bg-primary`, `--bg-surface`, `--bg-card`, `--text-primary`, `--text-secondary`, `--text-accent`, `--border-color`, `--control-border`, `--card-shadow` and `--glass-background`. Existing glass colors remain 85% dark and 92% light with 15px blur. Focus outlines use `--text-accent` rather than a low-contrast decorative border.

Role charts use `--chart-axis`, `--chart-grid` and the eight series tokens. CSS updates these immediately when theme changes, without refetching analytics or clinical history. Chart entry animation is 450ms and disabled for reduced motion. Historical kidney charts retain their existing non-animated measured-value line and accessible table.

## Accessibility and responsive behavior

- Shared buttons and primary controls retain a minimum 44px touch target and visible keyboard focus.
- A skip link targets the main content. Card surfaces no longer use a hover wrapper that clips dropdowns or shifts entire forms.
- CKD model inputs have explicit Required badges and `aria-required`; errors have text and an indicator, are linked to their fields and focus the first invalid numeric or categorical input.
- Reduced motion disables CSS entry/decorative movement and hover transforms; Framer Motion also honors the system preference.
- Headers/actions wrap, clinical grids retain responsive columns, outer views stack below 768px and data tables scroll inside their containers. Existing registration one/two/three-column rules are preserved.
- Target viewports remain 375, 768, 1366 and 1920px. Live verification is pending as recorded in the testing report.

## Extend the system

Use PageHeader for new page titles, Card for task panels, Input/Select/Button for controls and semantic status badges for warnings or risk states. Keep clinical warnings separate from decorative headers. Use the chart token helpers for data marks. Add color changes only in `colors.ts`, regenerate tokens and run the theme checks. Keep patient state in the authenticated in-memory workspace or approved backend drafts; this integration stores no clinical data in localStorage.
